## Product

Eevee is a local-first terminal workbench for LLM-assisted development. Your own party of Eevee partners retains the task, evidence, and decisions while specialized forms expose the right tools; each partner switches form freely, and several partners may cooperate on one task. It is not another full-screen chat log or nine permanently running agents: idle partners do nothing and cost nothing.

Use Eevee and its eight existing evolutions; do not invent additional species. Species and types follow the original concept. Software responsibilities below are product interpretations, not claims about canonical abilities. Forms are reversible workbench states, not a simulation of the games' evolution restrictions.

### Experience: a partner, not a themed dashboard

- **Sanctuary** is Eevee's home: request input and the active response, with saved task facts and specialist details available on demand. With no task, invite the user to type a request, not complete a Goal setup or visit nine empty specialist dashboards.
- **Partner** is one individual Eevee in the user's party: nickname, current form, met date and its own learned moves. The lead partner is the one in front of the current task; other partners may be idle or working on the same task.
- **Evolution** changes the tools for the same task. Keep the task identity, selected evidence, decisions, and user-approved scope across forms. The role is independent of the selected execution agent/model; changing either selection does not itself submit a request.
- **Field journal** is the task's inspectable evidence history: observations, decisions, executions, reviews, and handoffs. Cosmetic form selection is not evidence. Opening the journal performs no model call.
- **Bond** means explicitly approved project/personal habits that save repeated instructions. No affection score, XP, hunger, streaks, random unlocks, or inaccessible forms.
- **Evolution Stones** are task recipes, not collectible currency. All nine forms remain locally selectable; recipes do not imply every canonical species evolves through a stone.
- **Moves** are a partner's named, single-form reusable actions: exact approved argv/cwd, context selectors, a submitted user-authored instruction, or a goal/criteria template. Four active moves per form; every use still needs ordinary review. Moves carry no permissions, provider output or memories.
- Keep original species names/types and visual cues, but use plain developer verbs for actions. Do not rename a failing command as a successful “attack” or conceal errors behind character dialogue.
- The companion is a small upper-right accent, not a full-height dashboard column. Personality comes from the original species sprite, restrained elemental UI accents, and factual status. Never insert unsolicited chat or animate the portrait. A small, optional activity spinner may accompany real in-flight provider work; it is not progress evidence and stops for local decisions, permission input and idle state.

### First useful journey

1. Choose an explicit provider route and model if needed. Native Codex responses and the Codex CLI agent are separate searchable choices with distinct tool, credential and session boundaries. Named `/connect <route>` opens setup directly.
2. Type in the primary composer and press Enter to save and send. Ctrl+S only saves locally. Local preparation, storage acknowledgment and admission checks still bind the exact submitted input.
3. Review only meaningful effects: commands, file changes, elevated/write-enabled sessions, project executables or unmanaged connections. Exact payload review remains available through advanced session requests; no blanket grant is remembered.
4. Read the response inline and type a follow-up. A changed model advances to advertised reasoning choices, then returns to the same editor; accepting the unchanged model/effort pair returns directly, with `/effort` still available. Opening a picker clears any armed underlying review, so a shortened return cannot grant a request. Nonsecret choices survive restart; explicitly saved app credentials are separate from preferences. Native chat history, provider sessions and permissions are never restored.
5. Use source, execution, review and handoff commands directly when the task needs them. No journey requires visiting every form.
6. Closing/reopening preserves the task and each partner's request draft, but never restores approvals or runs work automatically.

Everyday navigation uses the existing action registry: common home actions precede advanced session controls, duplicate alias rows are collapsed except for exact queries, and search keywords live in the locale resources. Search/browsing never grants authority. Source Preview/Payload Tab returns directly to Files with filter/selection intact; `/basket` retains explicit attachment inspection, and capture review remains required. Selecting the active task only returns through existing overlay/composer ownership; another task still requires every persistence/work guard. Missing retained model IDs focus Custom rather than accidentally refreshing metadata.

Clean exit waits for local preference writes and optional history persistence without an empty all-owner cancellation review. Pending sends/commands, active requests, unresolved outcomes, failed journals and unsaved drafts retain their existing neutral safety decisions; no pending intent may dispatch while exiting.

This is a route, not a mandatory tour through every form. Skip irrelevant forms; never issue model calls just to fill a progress trail. The smaller local-only milestone is create task -> exit -> resume -> inspect sources; it must be useful before a provider is connected.

### Boundaries

- Eevee accepts ordinary requests without manual specialist setup. In automatic mode, the explicit send locally selects the appropriate form before ownership/preparation; ambiguous follow-ups keep the current form. Espeon designs rather than acting as a mandatory intake step. Automatic routing never overrides explicit Plan/Review or permits writing without exact consent.

### Accessibility and visual quality gates

- Keep a linear text/activity layout with the same actions and state labels; portraits are optional, never the only identity/status signal. Do not claim screen-reader compatibility before exercising a real assistive terminal setup. Reduced visual detail does not reduce approval controls or evidence.
- For the application's own true-color themes, target at least 4.5:1 text contrast and 3:1 focus/control contrast; verify selection, errors, muted text, and both backgrounds. Unknown user terminal palettes require monochrome/reverse/focus-marker fallbacks, not an unmeasured contrast claim.
- No blinking, animation-dependent meaning, mandatory icon font, or color-only distinction. Truncate display paths/titles with a visible continuation affordance; inspection reveals exact values before approval. Never truncate the only visible executable or affected scope without an expansion control.
- Run actual TUI scenarios across the supported size/theme matrix: first-run empty, missing agent/art, loaded task, long CJK draft, pending permission/question, large streaming output while scrolled, cancelled run, save failure, stale review, provider switch, and return after interruption.
- User-success criteria: a new user can find the next action without opening help; can identify active task/form/agent and control limitations before sending; cannot execute by navigation/paste; can stop work and recover their draft; can explain why a result is or is not verified. Record observed scenario outcomes, not subjective “looks polished” alone.

## Task and evidence model

A task owns its goal, acceptance criteria, current form, agent-profile selection, independent request/storage/evidence state, decisions, source references, changes, executions, findings, permissions, and handoff. Forms exchange a compact envelope: goal, scope, evidence references, unresolved items, requested action, and completion condition. Provider session references are profile-scoped and never portable grants.

Separate observed facts, model inferences, and user decisions. Persist provenance for each. A command result contains cwd, sanitized arguments, start/end time, exit/signal status, output references, and before/after code-state identities. A passed command is not proof of every requirement.

Capture the initial working tree without overwriting user changes. Git metadata and baseline file identities distinguish pre-existing changes from session changes; concurrent external edits remain unattributed rather than falsely assigned to the agent. A code-state identity covers relevant tracked and untracked inputs, not only HEAD. Changes during a run make its association ambiguous; changes after a run make its verification stale. Display unknown coverage explicitly.

Legacy Phase 1 surfaces use a simple ready state. Planned task/request/storage/evidence axes are defined above; task completion is separate from request success and requires the explicit acceptance checklist plus visible unresolved risks.

### Task lifecycle and local retention

- Completion requires an explicit state transition. Changing the goal or acceptance criteria of a completed task requires deliberately reopening it; an old verdict must not imply the new criteria passed.
- Archive hides a task without deleting its evidence. Delete/purge is separate: preview the affected task records, drafts, output/assets, and shared references, then require confirmation with neutral initial focus and a no-effect Cancel path. Do not purge active work or silently sever its evidence.
- Redact identifiable credentials before any metadata, journal, or output-spool persistence; do not promise perfect detection. Provide configurable spool quotas and retention with visible disk-pressure behavior. Never silently evict active evidence; when capacity is exhausted, stop further capture/execution safely and expose the limitation rather than recording complete evidence.
- Retention and explicit deletion must show missing artifacts as unavailable, not empty or successful results. Preserve memory/profile records still referenced by other tasks; task deletion is not blanket shared-state deletion. Explain local scope: purge is neither secure erase nor deletion of provider-owned sessions/data. Command runners and durable-memory flows inherit these rules.

## Permissions and recipes

- Capabilities are enforced at the execution boundary, not merely described in prompts.
- Reading, writing, command execution, network access, and durable memory are separate capabilities. An external CLI without enforceable restrictions must be labelled unmanaged; do not present it as sandboxed.
- Approvals show exact arguments or shell text, cwd, affected scope where known, and permission duration. Unknown command effects remain unknown.
- Imported recipes are untrusted configuration. Loading one neither runs commands nor grants permissions.
- Evolution Stones are versioned TOML recipes specifying form workflow, allowed scope, context selection, validation commands, and completion criteria. A recipe cannot widen existing grants.
- Memory is task-local, project-local, or personal. Promotion to project/personal memory requires explicit approval and supports inspection, editing, and deletion.
- Treat terminal output, repository text, and external sources as untrusted content. They cannot modify grants or issue application commands. Strip unsafe terminal control sequences before rendering.

## Implementation stack and efficiency

Choose Rust with Ratatui and Crossterm for the native TUI, Tokio for asynchronous I/O and subprocess coordination, Serde for schemas, TOML for recipes, and SQLite through rusqlite for durable task metadata. Store large command output in bounded/rotated local files referenced by metadata. Begin with one Cargo package and explicit modules, not a multi-crate framework.

Rust offers native startup, predictable memory ownership, and no garbage-collector pauses. This is a fit-for-purpose decision, not a claim that any language is universally fastest. Model/network latency will usually dominate agent work; reducing unnecessary context and calls matters alongside rendering efficiency.

Claude uses an optional TypeScript SDK sidecar for its documented interactive lifecycle. Explicit setup/update fetches the latest stable SDK; reviewed installed metadata, loaded-code paths, dependency-tree identity, bridge revision and mandatory policy controls must match before prompt release. This is a compatibility choice, not a mandatory runtime or second UI implementation. Start it only for the selected provider; the native shell and other adapters work without it. Keep IPC narrow, versioned and bounded; compare actual resource cost rather than assuming a bridge is free.

- One terminal owner; blocking Git/SQLite/filesystem work stays off the rendering path.
- Bounded worker channels; batch stream updates. Preserve output on disk while virtualizing the visible window; do not grow an in-memory transcript forever.
- Invalidate only changed views; redraw on input/visible-state changes, at most30fps during streams, never on an idle timer alone. Apply correlated background cache results without repainting an unchanged hidden view; restoration readiness is not a visible-change signal. Actual model/pairing, habit/activity, held-reference and open-inspector changes still invalidate their surface.
- Cache parsing/diff results by source identity; avoid reloading the repository or recomputing all hashes per frame.
- Launch commands with direct argv and no implicit shell. Shell execution separately identifies the executable, dialect, and exact shell text; `.cmd`/`.bat` require an explicit shell path, not a silent wrapper. Establish native process-tree ownership before offering safe cancellation: owned process groups on POSIX, Job Objects or an equivalently verified tree-ownership mechanism on Windows. If ownership cannot be established, reject the safe-cancel action rather than advertising it. Track partial output, exit status, and terminal recovery; external-agent cancellation follows its actual protocol, and timeout/forced teardown remains outcome unknown unless tree exit is verified. Never claim that cancellation undoes changes.
- Select context by scope and evidence references; do not inject every form prompt or the full historical transcript. Display provider-reported token counts separately from estimates, identify turn/session/cumulative scope, and disclose provider-added context that cannot be inspected. Do not invent savings percentages or sum incompatible counters.
- Local packet deduplication is structural, never lossy: a capture whose bytes are already present in another selected capture of the same `(root, path, source_sha256)` is emitted as a `same_bytes_as` citation that always resolves to a text-bearing entry — never a citation chain. Codex `edit_baseline` may cite a byte-identical whole-file capture instead of resending it. Distinct paths or revisions with identical text keep separate bytes. Oversized ACP tool observations are bounded by labelled head/tail elision (`truncated_by_eevee`, exact `total_bytes`/`omitted_bytes`) rather than aborting the provider session; receipts and drawers disclose deduplicated counts, and savings are never presented as provider cache hits or billing.
- Use one specialist request at a time initially. No background model chatter, automatic agent fan-out, or model calls for cosmetic transitions.
- Apply the task lifecycle and retention rules above to every persistence path, including command spools and durable memories.

Initial native local-shell performance acceptance targets, not measurements: idle CPU <1% of one core over 60s; idle RSS <=80 MiB; warm local startup to usable UI p95 <=200 ms over 30 runs; local key-to-render p95 <=50 ms under streamed output. Record hardware, release profile, terminal size, sample method, and workload. Report optional SDK bridge and external-agent resources separately **and in aggregate**; a core-only number is not total application cost. Benchmark a 10 MiB output stream and a 10,000-line diff; memory must remain bounded by configured windows/queues. Optimize from measurements, not assumptions.
