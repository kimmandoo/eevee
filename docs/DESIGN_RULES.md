### Owned-request completion

- A successful provider turn is not proof that the owned logical request or local acceptance criteria were completed. Current request/generation/task/partner identity owns todo/tool/question observations; old task snapshots, old views, foreign work and future planning data do not create a new obligation or authority.
- Native non-Plan requests may continue forward after a no-tool terminal answer only when the current request mutated todo claims and actionable pending/active work remains. Retain the actual assistant turn and tool results, use the same frozen capabilities/lease/receipt and revalidate ownership/cancellation before every continuation. WebSocket continuation uses the authoritative response anchor and only the new reminder; never replay completed effects.
- Limit completion reminders to three within existing round, call, byte, output and wall limits. No useful result or substantive todo change stops further reminders; observation-cache hit/miss/timestamp/cost telemetry is not substantive progress. No-obligation answers and future Plan outputs remain terminal.
- Preserve blocked claims; continue only independent authorized actionable steps, never unblock or retry blocked effects implicitly. Denied permissions remain a stop boundary even after later successful observations. Errors, waiting prompts, unsettled tools, cancellation and unknown effects cannot be relabelled successful completion or trigger effect replay.
- Common settlement rejects known unfinished obligations across native and external adapters. External adapters are not automatically resubmitted; incomplete results remain incomplete. Provider todo claims are not local verification, and local criterion completion retains its separate reviewed-evidence boundary.

### Wave7 input and local-repository effects

- Screenshot input is an explicit, separately reviewed attachment of one bounded PNG/JPEG on a documented image-capable native Responses route. Freeze exact compressed bytes, decoded bounds, dimensions, source identity and selected route; containment, exclusions, application-storage protection and no-link rules apply. Unknown/unsupported capability, changed/deleted sources and excessive serialized bodies refuse rather than dropping or substituting the image. Display bytes and disclosure/retention/purge policy; terminal metadata/hash review is not visual inspection or secret redaction. Outgoing receipts account for actual serialized image bytes separately from unknown image-token cost. Removal/cancellation sends nothing; restart restores inspection/selection, never approval or replay. No URL fetching, automatic clipboard ingestion, OCR, PDF/audio/video or other-adapter expansion.
- Git observation remains read-only. GP07 adds only an explicitly authored, reviewed, one-shot local whole-file commit through the existing command approval, writer ownership, owned runner and durable evidence path. A supported ordinary repository must have a clean initial index and no merge/conflict operation. Freeze selected paths/content/modes, HEAD/ref, index, exact message, author/committer identities, executable and configuration effects; revalidate immediately before dispatch. Neither file-write consent, form/recipe selection nor standing agent-command approval authorizes this operation.
- The selected-commit path must enforce exclusion of hooks, clean/smudge/process filters, signing and executable helpers, with the mechanism and resulting Git semantics disclosed before consent; unsupported repository/configuration states refuse. Preserve all unselected working changes and never silently include staged work. Report the actual created commit and observed ref/index outcomes, including partial/unknown effects and potentially retained unreachable objects. A local commit is not verification. There is no push, authentication, branch/worktree management, rebase/conflict resolution, automatic retry/reset or claimed rollback.

The authorized follow-up adds request-owned native Responses WebSockets, not a universal provider-session framework. `--native-transport auto|http|websocket` is a native-only launch choice, frozen before preparation. Auto selects WebSocket only for the exact officially documented public OpenAI Responses endpoint; other existing endpoints retain HTTP. Keep `store:false`, existing full-history/context limits and actual frame/aggregate bounds. Retire connection/anchor on logical completion, cancellation, failure, malformed/cross-owner input, timeout or unknown outcome. Each new explicit user Send retains today's bounded completed-public-history rules, not prior private/tool items, remote write authority or a restored opaque chain. No cross-task/account sharing, speculative warmup, hidden steering, WebSocket reconnect, stale-ID replay or SSE fallback is permitted. Send only actual acknowledged tool-result items, optionally followed by explicit user steering items (XC03).

**Visible steering and queued Send (XC03, intentional change 2026-10-29).** Enter while the lead works offers `s Steer this run | q Queue as next Send | Esc Keep draft` (external routes offer only Queue/Keep). Steering is exact user-authored nonsecret control-safe text, at most 4 KiB, no attachments, eight waiting, bound to the current task/partner/generation. The worker appends it only at the next tool-result boundary: a user item for Responses/Chat, text blocks in the tool-result user turn for Messages/Gemini, trailing user items after WebSocket function outputs. `Steered` acknowledges local append, not independently proven provider delivery; its own receipt line says so. Text that never reaches a boundary returns with original whitespace/caret. A newer draft keeps its caret and recovered text is appended, never overwritten or sent. There is one process-local queued Send per task/partner (`/queue-cancel`); it dispatches through fresh preparation/review only after that exact run completed into its empty composer while that partner is in front. Bringing another partner forward never transfers or dispatches a queue; returning the owner may settle it. Failure/cancellation/unknown, changed generation or a newer draft returns it unsent. Choice keys are owner/generation-bound and neutral default preserves the draft.

**Bounded safe retry (XC04, intentional change 2026-10-29).** A native HTTP model round may be resent automatically only when the failure proves the provider did not process it: a connection error before the request was written (`is_connect`), or HTTP 429/503/529 before any body byte is read. At most three extra attempts per round, waiting 1/2/4 s plus jitter or an integer `Retry-After` of at most 60 s, inside the round deadline; the exact frozen round body and the same transport are reused. Any other status, any timeout or failure after the request was written, and any failure after a response byte stay as today (failed or outcome unknown, never resent). Tool effects are never repeated. Each wait is shown as a cancellable status (Esc during backoff ends the run as Cancelled with nothing in flight), the dispatch receipt is emitted once, and the completion message lists every retried attempt with its cause. WebSocket rounds are not retried. `--retry off` restores single-attempt behavior for the launch.

Freeze/disclose the actual WS destination and initial `response.create` frame before dispatch; HTTP and WS must not share a misleading POST-body receipt. An HTTP101 upgrade proves a connection, not model submission. Attribute one logical dispatch only to actual provider receipt evidence; ambiguous post-send failure remains unknown. Credentials remain exact-origin/path scoped, redirects are forbidden and unsupported proxy/TLS/dialect conditions refuse rather than silently changing transport or network policy.

TLS trust-root policy applies only to secure `wss://`. Existing validated ordinary cleartext loopback `ws://` routes do not perform TLS and therefore are not blocked by `SSL_CERT_FILE`/`SSL_CERT_DIR`; this does not permit insecure remote endpoints, bypass proxy routing or change secure-connection trust.

Bound assembled/fragmented messages before JSON admission, total bytes, queued events and public/tool output. Keep one attributable response at a time and reject mismatched identities/streams/sequences. Service ping/close/cancellation during permission waits without a second input owner or effect executor. Existing generation/credential/root/writer checks, exact one-shot file/command approvals, retained actual outcomes and no-replay guards remain authoritative across every round.

Existing request surfaces distinguish transport, completed public context and actual provider-session new/resume identities. Native requests never invent a provider thread. Retain bounded process-local request-bound terminal outcome/reason separately from item completeness, with public-context admission/exclusion labelled only where actually known. Concrete external EOF/pipe-I/O/unexpected-exit branches use the existing typed Transport diagnostic before terminal settlement; arbitrary provider errors, policy/storage failures and user cancellation are not reclassified. Diagnostics/remediation never reconnect, resend or grant automatically.

Deterministic WS/stdio peers and actual compact/wide TUI journeys qualify local wire, continuity, diagnostics and approval behavior. They do not establish live cache use, entitlement, billing or latency savings. SQL20/TM1/formation2 and complete SDKbridge11 remain unless an independently documented strict durable/IPC shape actually changes.


## Product

Your own party of Eevee partners retains the task, evidence, and decisions while specialized forms expose the right tools; each partner switches form freely, and several partners may cooperate on one task. ### Approval and agent-question UX

- One correlated queue holds pending requests with task, run, agent/profile, tool ID and approval/question ID. A question is not a permission grant.

- Offer only semantics actually supported by the adapter. An agent's `allow_always` is not automatically “allow for this Eevee task.” Broad/persistent options require explicit scope disclosure; hide them if their duration or boundary cannot be represented accurately.
- Revalidate before responding. If tool inputs, profile/config, run generation, or scope changed, invalidate the old answer and show the updated request. Expired or already-resolved requests are read-only; answering twice cannot dispatch twice.

### Operational, persistence, and evidence states

- Track independent state axes rather than one overloaded badge:
  - Task outcome: open, complete, cancelled.
  - Request: idle, connecting, running, awaiting permission, awaiting input, cancelling, succeeded, failed, cancelled, disconnected/outcome unknown.
  - Storage: draft, autosave pending, saving, saved, save failed.
  - Evidence: current, stale, ambiguous, unavailable.

Omit the chip rather than clipping higher-priority status.

Reconnect/resume is explicit and never replays a mutating request automatically; only the bounded safe retry of a provably unprocessed native HTTP model round is automatic, and it never repeats a tool effect. Reconcile already-applied changes before offering a new attempt.
- Save failures remain visible and retain recoverable draft content. On quit/switch, offer explicit retry-save, stay, or discard-unsaved choices; never present an unsaved task as durable. A provider-local session may persist independently and must not be confused with Eevee's own save result.
- Durable storage has an explicit schema/version and one writer. Detect another writer and expose the conflict without silent takeover. Migrate older schemas transactionally with a tested rollback/recovery path; never overwrite a corrupt or newer-schema database. Disk-full and locked-database failures retain the editable draft. Only a committed revision may be acknowledged as saved, and late acknowledgments must never regress the saved revision or label a newer draft saved.
- Coalesce implicit draft/caret/navigation/memory edits after 500ms of quiet, with a 2s maximum deferral during continuous edits outside active provider requests. Pending debounce is not in-flight I/O and must not poll the writer. A content request holds its exact committed input through dispatch, permissions and terminal acknowledgment: follow-up edits remain visibly pending in memory, including after Ctrl+S, until that ownership ends. Pre-output failure restores the original request when no follow-up was typed; otherwise retain the follow-up and submitted request separately. Outside this ownership hold, explicit saves, task/partner transitions and confirmed exit flush the latest snapshot. Safe exit cancels/waits before flushing. Only successful submission starts “saving”; old acknowledgments cannot clear newer pending work or failures.
- With active work, quit and Ctrl+C open a neutral-focus Stay / Cancel-and-exit decision, not an immediate process kill. Cancel-and-exit waits for acknowledgment or verified owned-tree exit with bounded escalation; unconfirmed teardown remains outcome unknown. Repeated keys must not accidentally confirm or force-kill. Unsaved-state choices still apply, and neither cancellation nor exit promises file rollback.
- Choice controls keep the textual `[Selected]` marker and also paint that segment with the selected (accent/reversed) button style; unselected alternatives stay plain. The focused provider question/permission option line uses the same style, and question answering keeps the focused option and its description scrolled into view at 60×18. Consent reviews keep manual scrolling and never arm by scrolling. Styling is not consent and never changes the neutral default.
- Error cards identify layer and remedy: image loading, local storage, agent executable, auth, capability/version, transport, model request, permission denial, or command exit. Preserve technical details behind an inspect action; transient notices do not erase the selected artifact or steal focus.

## Task and evidence model

A task owns its goal, acceptance criteria, current form, agent-profile selection, independent request/storage/evidence state, decisions, source references, changes, executions, findings, permissions, and handoff. Forms exchange a compact envelope: goal, scope, evidence references, unresolved items, requested action, and completion condition. Provider session references are profile-scoped and never portable grants.

Separate observed facts, model inferences, and user decisions. Persist provenance for each. A command result contains cwd, sanitized arguments, start/end time, exit/signal status, output references, and before/after code-state identities. A passed command is not proof of every requirement.

Capture the initial working tree without overwriting user changes. Git metadata and baseline file identities distinguish pre-existing changes from session changes; concurrent external edits remain unattributed rather than falsely assigned to the agent. A code-state identity covers relevant tracked and untracked inputs, not only HEAD. Changes during a run make its association ambiguous; changes after a run make its verification stale. Display unknown coverage explicitly.

Legacy Phase 1 surfaces use a simple ready state. Planned task/request/storage/evidence axes are defined above; task completion is separate from request success and requires the explicit acceptance checklist plus visible unresolved risks.

### Task lifecycle and local retention

- Completion requires an explicit state transition. Changing the goal or acceptance criteria of a completed task requires deliberately reopening it; an old verdict must not imply the new criteria passed.
- Archive hides a task without deleting its evidence. Delete/purge is separate: preview the affected task records, drafts, output/assets, and shared references, then require confirmation with neutral initial focus and a no-effect Cancel path. Do not purge active work or silently sever its evidence.
- Redact identifiable credentials before any metadata, journal, or output-spool persistence; do not promise perfect detection. Provide configurable spool quotas and retention with visible disk-pressure behavior. Never silently evict active evidence; when capacity is exhausted, stop further capture/execution safely and expose the limitation rather than recording complete evidence.
- **Forward-compatible task data (XC08, intentional change 2026-10-29).** The task `workflows` JSON and its `progress` and `game` members keep fields a newer writer added in `extra` and write them back unchanged; this reader no longer refuses them. A writer lists any field whose absence would change privacy, cost or effects in `workflows.critical` (dotted paths, e.g. `progress.eager_off` while the todo prelude is off); a reader that finds an unknown critical field refuses the task at load and save exactly like the earlier strict readers. Readers up to 0.1.37 still refuse every unknown field. The SQL schema stays major-only (`user_version`). Before migrating an older schema in place, the writer keeps a consistent `VACUUM INTO` copy in `<data dir>-backups/` (the newest three), outside the store so snapshots and quotas never include it; a failed copy refuses the migration.
- Retention and explicit deletion must show missing artifacts as unavailable, not empty or successful results. Preserve memory/profile records still referenced by other tasks; task deletion is not blanket shared-state deletion. Explain local scope: purge is neither secure erase nor deletion of provider-owned sessions/data. Command runners and durable-memory flows inherit these rules.

## Permissions and recipes

- Capabilities are enforced at the execution boundary, not merely described in prompts.
- Reading, writing, command execution, network access, and durable memory are separate capabilities. An external CLI without enforceable restrictions must be labelled unmanaged; do not present it as sandboxed.
- Approvals show exact arguments or shell text, cwd, affected scope where known, and permission duration. Unknown command effects remain unknown.
- **Approval rules (XC01, intentional change 2026-10-29).** A remembered allow exists only as an explicit user-created rule with a displayed boundary. `/rule-allow` or `/rule-deny` while the lead's request is under review saves the narrowest rule for it: a **direct-argv command** pinned to the resolved executable path and SHA-256, a token-exact argv prefix (`/rule-allow N` keeps N arguments) and a project-relative cwd prefix; or a **file create/edit** of the exact path or a typed project-relative glob. Rules are per project, stored in `<data dir>/rules.json` (owner-private) or kept only until exit (`launch`). Matching order: an enabled Deny wins, then the most specific Allow, otherwise ordinary review. Rules never match deletes, renames, Shell-dialect commands, selected commits, external/out-of-project paths, another partner's request, questions, or anything while local effects are unknown. Every rule answer posts `Allowed/Denied by rule #N` with `/rules`, where rules are listed, disabled and revoked immediately; the third review of the same command prefix suggests a rule once, never creating it. Build/test rule sentences say they run project code; this is disclosure, not a sandbox. Model output, imports and navigation cannot create, widen or match rules.
- **Unmanaged MCP (XC05):** user-registered native stdio servers are unmanaged capabilities, never sandboxes. Eevee enforces exact direct-argv launch, current project/cwd, explicitly named inherited environment (values masked and fingerprint-pinned), process-tree ownership, selected frozen schemas, call review/rules and bounded untrusted results; it cannot constrain the server's internal effects. `/mcp add <JSON>` reviews and saves registration without launching; `/mcp connect <name>` requires a separate fresh launch review and initializes/lists tools once. Registrations are per-project in private `<data dir>/mcp.json`, with forward-compatible extras/critical markers; connections, selections and user read markings are process-local and default off.
- Only explicitly selected MCP tools enter the packet; schemas and results count toward sent bytes. Every call displays server/tool/JSON arguments and the unmanaged label, unless an explicit user-created project `Mcp {server,tool}` allow/deny rule matches; that rule discloses that it covers any arguments. Annotations are untrusted advisory text and never grant permission. Task-wide auto-approval cannot grant MCP. Results are bounded to 64 KiB, control-safe, untrusted and journaled; server crash returns a tool error, not a fabricated lead failure. Cancellation owns and kills the server tree. Sampling, elicitation, resources and prompts are refused; roots disclose only the current project root.
- **Unknown unmanaged effects:** a counted project-shared lease is durably published before each MCP call; failure to persist refuses submission. Crash, cancellation, malformed/error response or missing acknowledgment leaves a sticky critical `uncertain_projects` marker. Concurrent successes clear only their own live count and never prior uncertainty. Startup restores the marker before rule/task-auto grants, reconnect and later success do not clear it, and native/MCP automatic effect grants refuse while fresh manual review and inference/tool-error continuation remain available. The chrome, MCP panel and receipts state unknown effects; no rollback, reconciliation or no-effects claim is fabricated.
- Imported recipes are untrusted configuration. Loading one neither runs commands nor grants permissions.
- Evolution Stones are versioned TOML recipes specifying form workflow, allowed scope, context selection, validation commands, and completion criteria. A recipe cannot widen existing grants.
- Memory is task-local, project-local, or personal. Promotion to project/personal memory requires explicit approval and supports inspection, editing, and deletion.
- Treat terminal output, repository text, and external sources as untrusted content. They cannot modify grants or issue application commands. Strip unsafe terminal control sequences before rendering.

## Implementation stack and efficiency

Choose Rust with Ratatui and Crossterm for the native TUI, Tokio for asynchronous I/O and subprocess coordination, Serde for schemas, TOML for recipes, and SQLite through rusqlite for durable task metadata. Store large command output in bounded/rotated local files referenced by metadata. Begin with one Cargo package and explicit modules, not a multi-crate framework.

Rust offers native startup, predictable memory ownership, and no garbage-collector pauses. This is a fit-for-purpose decision, not a claim that any language is universally fastest. Model/network latency will usually dominate agent work; reducing unnecessary context and calls matters alongside rendering efficiency.

Claude uses an optional TypeScript SDK sidecar for its documented interactive lifecycle. Explicit setup/update fetches the latest stable SDK; reviewed installed metadata, loaded-code paths, dependency-tree identity, bridge revision and mandatory policy controls must match before prompt release. This is a compatibility choice, not a mandatory runtime or second UI implementation. Start it only for the selected provider; the native shell and other adapters work without it. Keep IPC narrow, versioned and bounded; compare actual resource cost rather than assuming a bridge is free.

- One terminal owner; blocking Git/SQLite/filesystem work stays off the rendering path.
- Bounded worker channels; batch stream updates. Preserve output on disk while virtualizing the visible window; do not grow an in-memory transcript forever.
- Invalidate only changed views; redraw on input/visible-state changes, at most30fps during streams, never on an idle timer alone. Apply correlated background cache results without repainting an unchanged hidden view; restoration readiness is not a visible-change signal. Actual model/pairing, habit/activity, held-reference and open-inspector changes still invalidate their surface.
- Cache parsing/diff results by source identity; avoid reloading the repository or recomputing all hashes per frame.
- Launch commands with direct argv and no implicit shell. Shell execution separately identifies the executable, dialect, and exact shell text; `.cmd`/`.bat` require an explicit shell path, not a silent wrapper. Establish native process-tree ownership before offering safe cancellation: owned process groups on POSIX, Job Objects or an equivalently verified tree-ownership mechanism on Windows. If ownership cannot be established, reject the safe-cancel action rather than advertising it. Track partial output, exit status, and terminal recovery; external-agent cancellation follows its actual protocol, and timeout/forced teardown remains outcome unknown unless tree exit is verified. Never claim that cancellation undoes changes.
- Select context by scope and evidence references; do not inject every form prompt or the full historical transcript. Display provider-reported token counts separately from estimates, identify turn/session/cumulative scope, and disclose provider-added context that cannot be inspected. Do not invent savings percentages or sum incompatible counters.
- Local packet deduplication is structural, never lossy: a capture whose bytes are already present in another selected capture of the same `(root, path, source_sha256)` is emitted as a `same_bytes_as` citation that always resolves to a text-bearing entry — never a citation chain. Codex `edit_baseline` may cite a byte-identical whole-file capture instead of resending it. Distinct paths or revisions with identical text keep separate bytes. Oversized ACP tool observations are bounded by labelled head/tail elision (`truncated_by_eevee`, exact `total_bytes`/`omitted_bytes`) rather than aborting the provider session; receipts and drawers disclose deduplicated counts, and savings are never presented as provider cache hits or billing.
- Use one specialist request at a time initially. No background model chatter, automatic agent fan-out, or model calls for cosmetic transitions.
- Apply the task lifecycle and retention rules above to every persistence path, including command spools and durable memories.

Initial native local-shell performance acceptance targets, not measurements: idle CPU <1% of one core over 60s; idle RSS <=80 MiB; warm local startup to usable UI p95 <=200 ms over 30 runs; local key-to-render p95 <=50 ms under streamed output. Record hardware, release profile, terminal size, sample method, and workload. Report optional SDK bridge and external-agent resources separately **and in aggregate**; a core-only number is not total application cost. Benchmark a 10 MiB output stream and a 10,000-line diff; memory must remain bounded by configured windows/queues. Optimize from measurements, not assumptions.
