Capability/session-list inspection never dispatches a model or authorizes an unknown session. After a definite terminal outcome, an explicit neutral owner/task/request-bound review may discard only provably unsaved failed write attempts, revalidating their complete FIFO identities and errors; committed observations remain and a bounded memory-only coverage-gap notice survives. Running work, unknown outcomes, ambiguous commits, reads and purges cannot use that recovery. Reviewed schema-1 handoffs omit sessions/grants/private reasoning/credentials; imported claims stay unverified and stale dispatch bindings fail closed.

Implemented authentication boundary: local tasks never require an account. Discovery, version probing, explicit official login/status and model submission are separate actions. Login reviews disclose provider-owned browser/network/credential/configuration effects, require a visible summary at 60×18 or larger and committed idle state, and lend/restore terminal ownership. Codex browser/device OAuth and OpenCode's native chooser are available. Gemini authentication uses an explicitly labelled external native CLI handoff: choose Google OAuth/browser/manual-code, API key or Vertex there; its CLI may continue into chat, but Eevee sends no task/prompt and does not collect codes. No task is replayed afterward. Claude SDK never reuses claude.ai subscription OAuth; permitted API/cloud routes include separately opted-in provider-managed SSO/ADC chains. Unconfirmed authentication/cancellation stays unknown, and fresh login cannot erase a prior unresolved outcome.

Devin CLI offers dedicated native browser OAuth and explicitly selected manual-token login, with provider-owned status output. Tokens and credential stores never enter Eevee. Login/status exit alone remains unknown; task submission requires separate approval. Its local ACP agent retains the external-tool boundary, with managed Review and controlled implementation refused. A separate Eevee-owned website OAuth route (authorization-code + PKCE against server.codeium.com, loopback callback or pasted redirect) returns a Windsurf session credential that exists only in process memory: it is never serialized, journaled, logged or shown, Debug output is redacted, and bytes are scrubbed on drop. Eevee injects it only into the launched `devin acp` child's environment as WINDSURF_API_KEY; it takes precedence over stored credentials, expires from JWT exp minus five minutes, and expiry is a launch blocker on the next review. A successful native Devin CLI login clears the in-memory credential.

First-use contract: the primary composer accepts a request immediately; no separate Goal setup is required. Enter saves and sends the exact request after matching durable acknowledgment and immutable local preparation; ordinary qualified requests do not require a second popup. The first request initializes an empty task goal; follow-ups preserve existing facts. Ctrl+S saves locally without sending. Commands, file changes, privilege expansion, write-enabled sessions, project-supplied runtimes, external credential-helper chains and unmanaged tool connections retain scope-specific review. `/new` and `/resume` are ordinary Request actions everywhere; `/session-new` and `/session-resume` retain advanced exact-payload review. Missing connection setup preserves the draft but never replays the old send intent. Responses stream on the home workspace. Provider/model/role selection never submits a request. Paste never sends or navigates; artwork actions retain separate review.

Implemented E/F boundaries: schema 6 preserves task-local hypotheses, bounded refactor contracts/baselines, evidence-linked findings, guarded review verdicts and recipe plans/drafts. A supported diagnosis requires explicitly linked current source and run observations; failed diagnostics remain actual failures. Comparisons require distinct ordered complete passing runs of the same command/cwd/executable and current post-change identity; a single elapsed-time pair is not a speedup claim. Review uses freshly revalidated requirements/patch/selected observations, not implementation history or imported handoff; managed Review has no Resume/write grants, and ACP Review is refused. Accept is re-evaluated against current criterion evidence rather than trusting its persisted label.

Curated memory and recipe consent: approved task/project/personal notes use the existing single SQLite writer. Scope/provenance/content are previewed, approval is neutral, and outgoing selection is separate; dispatch revalidates exact selected identities/revisions and deletion removes future context without claiming historical erasure. Task deletion preserves project/personal records. Strict schema-1 local TOML recipes may stage a plan/criteria/context proposals/validation argv only; unknown capability fields cannot grant authority. Documentation writes keep their own preview/approval. Specialist editors retain grapheme-safe drafts and refuse affirmative operations below 60×18.

## Product

Eevee is a local-first terminal workbench for LLM-assisted development. Your own party of Eevee partners retains the task, evidence, and decisions while specialized forms expose the right tools; each partner switches form freely, and several partners may cooperate on one task. It is not another full-screen chat log or nine permanently running agents: idle partners do nothing and cost nothing.

Use Eevee and its eight existing evolutions; do not invent additional species. Species and types follow the original concept. Software responsibilities below are product interpretations, not claims about canonical abilities. Forms are reversible workbench states, not a simulation of the games' evolution restrictions.

### Experience: a partner, not a themed dashboard

- **Sanctuary** is Eevee's home: request input and the active response, with saved task facts and specialist details available on demand. With no task, invite the user to type a request, not complete a Goal setup or visit nine empty specialist dashboards.
- **Partner** is one individual Eevee in the user's party: nickname, current form, met date and its own learned moves. The lead partner is the one in front of the current task; other partners may be idle or working on the same task.
- **Evolution** changes the tools for the same task. Keep the task identity, selected evidence, decisions, and user-approved scope across forms. The role is independent of the selected execution agent/model; changing either selection does not itself submit a request.
- **Field journal** is the task's inspectable evidence history: observations, decisions, executions, reviews, and handoffs. Cosmetic form selection is not evidence. Opening the journal performs no model call.
- **Bond** means explicitly approved project/personal habits that save repeated instructions. No affection score, XP, hunger, streaks, random unlocks, or inaccessible forms.
- **Evolution Stones** are task recipes, not collectible currency. All nine forms remain locally selectable; recipes do not imply every canonical species evolves through a stone.
- **Moves** are a partner's named, single-form reusable actions: exact approved argv/cwd, context selectors, a submitted user-authored instruction, or a goal/criteria template. Four active moves per form; every use still needs ordinary review. Moves carry no permissions, provider output or memories.
- Keep original species names/types and visual cues, but use plain developer verbs for actions. Do not rename a failing command as a successful “attack” or conceal errors behind character dialogue.
- The companion is a small upper-right accent, not a full-height dashboard column. Personality comes from the original species sprite, restrained elemental UI accents, and factual status. Never insert unsolicited chat or animate the portrait. A small, optional activity spinner may accompany real in-flight provider work; it is not progress evidence and stops for local decisions, permission input and idle state.

### First useful journey

1. Choose an explicit provider route and model if needed. Native Codex responses and the Codex CLI agent are separate searchable choices with distinct tool, credential and session boundaries. Named `/connect <route>` opens setup directly.
2. Type in the primary composer and press Enter to save and send. Ctrl+S only saves locally. Local preparation, storage acknowledgment and admission checks still bind the exact submitted input.
3. Review only meaningful effects: commands, file changes, elevated/write-enabled sessions, project executables or unmanaged connections. Exact payload review remains available through advanced session requests; no blanket grant is remembered.
4. Read the response inline and type a follow-up. Model selection advances to advertised reasoning choices, then returns to the same editor. Nonsecret choices survive restart; explicitly saved app credentials are separate from preferences. Native chat history, provider sessions and permissions are never restored.
5. Use source, execution, review and handoff commands directly when the task needs them. No journey requires visiting every form.
6. Closing/reopening preserves the task and each partner's request draft, but never restores approvals or runs work automatically.

Clean exit waits for local preference writes and optional history persistence without an empty all-owner cancellation review. Pending sends/commands, active requests, unresolved outcomes, failed journals and unsaved drafts retain their existing neutral safety decisions; no pending intent may dispatch while exiting.

This is a route, not a mandatory tour through every form. Skip irrelevant forms; never issue model calls just to fill a progress trail. The smaller local-only milestone is create task -> exit -> resume -> inspect sources; it must be useful before a provider is connected.

### Boundaries

- Eevee accepts ordinary requests without manual specialist setup. In automatic mode, the explicit send locally selects the appropriate form before ownership/preparation; ambiguous follow-ups keep the current form. Espeon designs rather than acting as a mandatory intake step. Automatic routing never overrides explicit Plan/Review or permits writing without exact consent.
- Vaporeon gathers context; Umbreon tests explanations of a failure or risk.
- Flareon changes behavior; Leafeon improves structure or efficiency within an agreed behavioral contract.
- Jolteon records execution, not correctness judgments. Provider-native tool runs may be observed in its journal without being launched by Eevee; never duplicate them to simulate control. Glaceon judges evidence and never silently fixes its own findings.
- Sylveon records verified conclusions, not invented success or inferred user preferences.
- One active form per partner. An idle partner switches form freely and instantly; switching is local UI/state work and must not trigger a model call by itself.
- Forms may change through deliberate selection or EV18 automatic mode at an explicit ordinary Request send. Choosing a specialist fixes manual mode; returning to Eevee re-enables automatic selection/default policy. Mode and current form persist per partner in Schema 16; old specialist choices remain manual after migration. No confirmation dialog is required, and evolution itself grants no permission or execution.
- Automatic intent selection uses one bounded local English/Korean rule table, not model calls, provider output, pasted/quoted source, metadata browsing or self-activated recommendations. Busy/cancelling/pending work is never reclassified. The transition preserves partner/draft/evidence and provider/model/effort, does not apply saved pairings or resume opaque cross-role sessions, and is reflected in the frozen new request. Necessary new role context is disclosed while the displayed transcript remains intact.
- Once automatically evolved, keep competing advisory-form banners out of the response viewport; the explicit suggestion inspector/picker retains that evidence, and manual forms retain their advisory strip. Automatic selection and transition feedback must not require dismissing an unrelated recommendation before reading the answer.
- Evolution disclosure is transient: retain it through passive resize/key-release events and yield its rows on the next deliberate key/paste without consuming that input, changing the selected form or altering the frozen request.
- `/eevee` (or `/normal`) and the top `Return to Eevee / intake` picker action return the lead to intake without replaying work. `Home` selects the top action; Up reaches it from the first grid row/list entry, Down resumes form preview, and Escape keeps the current form. Task facts, draft text/carets and retained evidence are unchanged; form identity, previous-form navigation, revision and save time are expected to change. Owned local work keeps Stay / cancel-and-wait; provider work requires explicit neutral-default cancellation and waits for local terminal completion plus journal settlement. Unresolved tool/effect outcomes, journal failures and another partner's active request prevent an automatic return.
- Out-of-role command preparation (`/command-edit`) names Jolteon. Eevee's ordinary coding surface, Flareon and Leafeon may locally select exact source restrictions (`/paths`) or Implement; neither action grants writes. Other forms offer a deliberate switch to Flareon. The switch never replays the refused action, submits a request, prepares a command, opens a write editor or grants permission. Existing neutral reviews and active-work guards retain priority; `/run` remains available to every form for inspecting execution evidence.
- Jolteon's empty-state primary action is `/command-edit`: author a command directly. `/run` inspects retained execution state; `/execute` opens the prepared command's required one-shot permission review. No entry action executes work.
- The owning-form offer also names idle partners already in that form. `Send to <partner>` uses the same reviewed reference relay: it pre-fills only that recipient's Request, never replays the refused command/path/role action, invents argv or editable paths, or transfers permission.
- After a successful form switch, a transient one-line carry-over record shows `C` (stored criteria met/total), `P` (committed task pins), `H` (open hypotheses), `F` (unresolved findings), and capability additions/removals from the same role capability table. Supported/refuted hypotheses are not open; unresolved/conflicting or unavailable proof remains open. These counts describe retained local state, not verification or permission grants. Source/run hydration settles before recording counts, rather than presenting pending evidence as zero.
- The carry-over line takes the existing home status slot without moving the composer or replacing retained output. It fades on the next real key/paste while that input is processed normally; resize, release-only keys and background settlement do not dismiss it. Companion `c` or `/carry-over` reopens the exact last switch record, including after an input hid it before delayed settlement. A preview, same-form selection, refused/cancelled switch or task restoration creates no switch record; task/new-task/lead transitions clear it. No persistence, provider/handoff context, execution or grant is added.
- Carry-over hypothesis guards are cached off-render by task-owned evidence metadata and repository observation; the recommendation and carry-over readers share one observed fingerprint. Form/draft/nickname-only changes do not reread sources. Deliberate specialist refresh invalidates cached hypothesis counts even if serialized metadata is unchanged. ASCII `+`/`-` capability differences stay descriptive and never authorize an action.
- Shared state does not imply shared prompts: specialist requests contain only relevant evidence and constraints.
- Independence in Glaceon means a separate review context with the requirements, patch, and observed evidence; it does not imply a different model or guaranteed correctness.

### Party

Status: PT02–PT05 shipped the party store, roster/add, direct lead selection, named form switching and per-(task, partner) drafts/carets. Schema 8 enlarged Schema 7's reserved draft column; Schema 9 added the independent Request draft and its capacity bound. Existing task drafts transfer to their lead; the composer names its owner and draft-discard decisions affect that draft only. PT06A attributes new runs and provider journal records to partner id plus name/form snapshot (older records remain `partner unknown`). PT06B/PT06C keep requests/events/approvals and asking-partner identity with their original owner across front changes; stale/foreign events are refused. Wave 4 shipped three independently owned provider/local-command participants with one durable Schema 13 write lease, permanent moving-run evidence, FIFO consent, scoped cancellation, responsive board and reviewed idle non-last release. Exact terminal/journal/ownership settlement is required; neither fronting nor restart replays work or transfers permissions.

- **Size:** up to **6** partners in the party. A new partner starts as Eevee. Releasing a partner deletes its moves and pairings but never its evidence; evidence keeps a name snapshot of the partner that produced it.
- **Concurrency:** up to **3** partners may work on one task at the same time. Each partner owns its own draft, requests, approvals, questions and cancellation. Every journal entry, provider event and approval carries (task, partner, request); a late or stale event is never routed to another partner.
- **One writer:** edit-capable work (Flareon, Leafeon) takes a per-task write lease. Another partner's edit waits; a run started while the lease is held is recorded as `revision moving` and is not fresh verification. The lease is released on completion, cancellation and crash recovery.
- **No autonomy:** partners never start work on their own and never trigger another partner's work. Handing work to a partner pre-fills its draft with references only: no approvals, sessions or grants move.
- **Visible cost:** each provider request keeps its own explicit send intent and receipt; cooperation never merges grants or hides per-partner cost.
- **Review independence:** a Glaceon review by a partner other than the patch author is preferred; the same partner is allowed and labelled `same partner`.
- **Flavor stays local:** nicknames, partner names and dialogue never enter provider packets or handoffs.
- **Nicknames:** `/nickname`, Companion `n`, or roster `n` edits a personal-scope name through the existing single store worker and reserved nickname column. Trim outer whitespace; empty clears to `Eevee #n`. New names are bounded by 12 Unicode graphemes and 512 UTF-8 bytes, reject unsafe controls, and are unique among party nicknames using Unicode lowercase comparison without rewriting Unicode normalization. Enter saves locally; Escape cancels; storage refusal retains the candidate for correction/retry and identity changes only after committed acknowledgement.
- Header/composer identify `Nickname (Species)`; species/type remain visible or in the companion surface. Compact headers retain route/model/effort and species, clipping only overlong nickname/project display with a continuation marker; the composer/editor retain the full name. Renaming never changes task text, grants, prepared provider input or existing attribution snapshots. The request receipt reports **0 B of automatically added partner flavor**: this is not redaction of a name the user deliberately typed into task/source content.

### Moves

- **Ownership and scope:** at most four active moves per partner/form across visible project and personal scopes, including every project affected by a new personal move. Form switches retain inventory; another partner sees no implicit copy. Name uniqueness uses normalized Unicode case comparison per partner/form, including reminder history. User names remain bounded and editable; CJK is supported.
- **Shallow navigation:** `/move` or nonediting form-surface `m` opens a 2×2 menu at ≥90 columns and a list below it. Show kind and last observed outcome. Enter stages the selected move directly; optional `d` details expose steps, scope, provenance and usage. Closing restores the exact original Request bytes, caret and focus. Empty menus explain `/teach-move`; form-picker details show the actual saved inventory.
- **Teaching:** `/teach-move` previews the selected form's approved literal run, selected committed pin selectors, last actually submitted user-authored instruction, or current task goal/criteria. Never copy provider output, memories, grants or hidden context into a template. Teaching requires an explicit name/scope review and committed store acknowledgment before the inventory changes.
- **Revalidation:** run moves preserve ordered argv, including empty arguments, and portable project-relative cwd. Reject shell/environment launchers, environment assignments, masked/secret material, excluded/escaping paths and unsafe links. Context moves store only relative paths/ranges and resolve current captures at use; missing/excluded paths remain visibly unavailable. Filesystem checks run on existing workers, never the render/input reducer.
- **No inherited approval:** command moves use the existing runner's fresh preparation, identity checks and one-shot command review; no parallel executor. Each pin uses normal capture review and durable attachment. Request templates preserve a different nonempty draft, resolve reviewed selectors and open the full outgoing receipt before explicit Run. Task templates preview and explicitly apply goal/criteria with all criteria unchecked; completed/archived tasks refuse. Closing or changing the owning review invalidates late validation acknowledgments.
- **Local detection:** the same eligible approved argv/cwd, or canonical unordered pin set actually dispatched in a request, produces one candidate at three distinct committed sources for that partner/project. Different argv do not merge; invalid/secret commands never become candidates. Detection makes no model call. An idle-only learning prompt offers Learn, Not now, Never; opening it is durably recorded. Never survives restart; Not now waits three further matching uses. No prompt interrupts running work, reviews, dirty drafts or storage settlement; learning never starts work.
- **Replacement and reminder:** learning a fifth move offers the four current slots with their exact scopes and revisions, or neutral Give up learning. An atomic confirmed replacement forgets only the chosen current record. Forgotten and postponed moves remain in `/move-reminder`; relearning retains identical steps and revalidates current scope/paths. Removing the last project task purges project moves/reminders and that task's usage/source references while preserving personal moves/reminders.
- **Naming and party teaching:** fixed local canonical-name lists and semantic suggestions are labels only; unused names are chosen deterministically, with local numeric disambiguation when needed. Renaming changes no steps, provider payload or evidence. The nine type lists in `src/workspace/moves.rs` are part of Q01's naming-rights review before future distribution. Teaching to a party member copies the same-form steps with current teacher provenance, handles the recipient's full slots through the same replacement flow, leaves the teacher unchanged and transfers no approval/session/grant.
- **Honest records:** usage links actual committed command journals or correlated actual provider submission receipts. Queue acceptance, preview, iterator release and model metadata are not dispatch. Native HTTP response headers, completed CLI/ACP prompt writes and an admitted correlated SDK submission acknowledgment are transport evidence, not model completion. Command exit-0 counts are observations, not correctness; denied/cancelled uses are separate. Provider completion/billing remain unknown when unreported; locally applying task facts or pins does not invent an execution exit code. Counts and source revisions survive restart.
- **Bounded persistence:** Schema 14 shares the existing single store worker, quota, strict row/schema inspection and transactional upgrade. Bound records, candidates, dispatch/source evidence and usage; refuse limits without eviction. Full transports retain intent. Failed move operations retain exact owner/bytes for explicit `/move-retry` or neutrally reviewed `/move-discard`; do not busy-loop or retry automatically. Quit waits for accepted writes and exposes failed writes instead of silently dropping them. Back up older stores; older writers refuse without mutation and downgrade is unsupported.
- **Boundary:** MV08B TM file export/import remains unimplemented. Names, local teaching provenance and other partner flavor never enter provider packets or handoffs automatically. No progression score, power, accuracy percentage or autonomy is inferred from move usage.

No session, permission or grant is remembered.

Raw capture bytes are not wire bytes; unavailable context blocks assembly. Dispatch revalidates the original frozen request. No live filesystem watch is implied.
- EV11 changes cached ordering/reasons only: every form uses the same eligible query match set. Failure/changed-path facts may affect rank, not eligibility or permissions; rendering does not read files.

### Extensible display language and response navigation

Fluent resources under `locales/<BCP47-tag>/*.ftl` are discovered and embedded at build time. English defines complete semantic keys; generated typed `Message`/`Template` IDs and named literal arguments prevent screen-level language branching or interpreting user data as templates. Missing localized keys use English rules. Static text and translated search labels borrow initialized caches without per-render I/O or per-key allocation; dynamic formatting allocates only its result. Catalog syntax, duplicate IDs, identifier collisions and required-variable inconsistencies fail the build.

Language precedence is `--language` → `EV_LANGUAGE` → the first nonempty `LC_ALL`, `LC_MESSAGES`, `LANG`. Explicit `auto` resolves that system locale anew; unsupported system locales fall back to English. Explicit tags must match embedded supported languages. Display language does not translate provider/model IDs, raw scope, user text, source evidence, original errors or permission payloads, and grants no effects.

Output is one bounded transcript across retained message, plan and tool segments, preserving immutable owner/request attribution. Response wheel movement applies only inside its viewport and pauses following. PgUp/PgDn traverse the transcript by viewport; nonediting Up/Down move lines across segment boundaries. Alt+Up/Down remain explicit item-inspection jumps. Home/Alt+Home reaches transcript start; End/Alt+End follows actual latest output. Paused identity/byte anchors survive append, earlier-segment growth, retention and reflow. Editor arrows/Home/End retain draft/caret behavior; overlays/reviews keep input ownership.

Provider usage is optional reported data bound to actual request/task/partner/route identities with explicit response/turn/session/pipeline scope. Merge partial snapshots without zeroing absent fields; deduplicate events and use cumulative baselines only when known. Never double-add reasoning/cache subsets. Unknown totals, tokenizer, remote completion and billing remain unknown. Native rounds retain explicitly local turn namespaces without invented provider response IDs. Codex preserves reported boundaries; SDK bridge 7 correlates submitted UUID and scoped usage. ACP accounting remains unknown where unsupported; implementation is not all-provider live qualification.

### Reviewed form relays

- `/locations` parses only the already-retained live window or selected output page, up to 128 distinct `path:line[:column]` references. Rust/cargo, Python tracebacks, Node/TypeScript and generic diagnostic syntax are accepted. Parsing never reads another spool page or opens a file; a page must belong to the selected run before parsing. References remain untrusted, not instructions.
- `Pin range` (location Enter or `/pin-location`) uses the existing bounded capture review, containment, exclusion, identity and single-writer persistence path. The four-line window ends at the referenced line; the stored capture records its task-owned originating run, shown in the basket details. Out-of-root, excluded, missing, linked and stale files are refused without changing existing captures.
- `/rerun` offers `Rerun with Jolteon` for an observed stale run. The relay retains exact argv/shell and cwd, prepares new identities and opens a fresh neutral one-shot command approval; own reruns do not need an extra reference-confirmation popup. Cancelling the relay or denying the command starts nothing. The new run cites `rerun_of`; the old record and its source revision are immutable. A different cwd or irreversibly masked retained command is refused, never silently substituted; author a new command when its original bytes cannot be recovered.
- Supported Umbreon hypotheses and unresolved Glaceon request-changes findings may stage a Flareon requirement with evidence references and proposed exact restrictions. Unresolved/refuted/conflicting hypotheses, stale evidence and unavailable scope are disabled with a reason. Controlled writes retain their native POSIX/Windows, eight-file/64-KiB bounds and separate actual content/parent approval; limit hits refuse rather than trimming.
- Relay target selection offers the sender's guarded form switch or an idle party member already in the target form. A neutral review precedes staging. Recipients receive local drafts/references only: no request, execution, session, approval or grant transfers. Sender drafts/carets remain unchanged when another partner is targeted; nonempty request drafts are never silently replaced. Partner names stay display-only.
- A relayed finding retains its referenced source ranges and pre-fix bytes. Only a change intersecting those ranges marks it `addressed, needs re-review` and stales the verdict; changing a different range is not a resolution. Returning to Glaceon uses fresh independent review context, preferring a partner other than the author and labelling the author `same partner`. Findings do not close automatically.
- `Add as criteria` starts from a deliberately chosen Espeon decision, stages editable items and flags duplicates. Only explicit confirmation changes the task; confirmed criteria retain their decision provenance across edits/restart and begin unchecked. A proposal is not evidence that a criterion passed.
- Leafeon's retained baseline chooser shows age/revision and eligibility reasons. Reuse requires complete passing stable evidence at the pre-refactor source identity and matching argv/cwd/executable; revision-moving runs are ineligible. Choosing a fresh baseline remains available. Comparisons require distinct before/after runs and display both durations without claiming a speedup from one sample.

### Evidence-based form recommendations

The current task may show one local `Suggested: <form> — <fact>` line on home and its task card. First match wins in this order:

| Observed task/evidence condition | Suggested form |
| --- | --- |
| Nonempty goal without acceptance criteria | Espeon |
| Acceptance criteria without committed task pins | Vaporeon |
| Latest task-owned local run failed | Umbreon |
| Observed source changes without a complete run at the current source identity | Jolteon |
| Complete passing current local run without a recorded review | Glaceon |
| Effective current accepted review | Sylveon |

No match shows nothing. Only Eevee-owned local run records count; provider observations and imported statements are not local runs. Newer unknown/cancelled/partial runs do not reuse an older pass. Accepted review is checked through the existing guarded evidence view, not its stored requested verdict. Suggestions are advisory and never select, send, execute, approve or enter provider packets.

Freshness follows the latest bounded repository observation; `/refresh` observes external source edits, not a claimed live file watch. Report fingerprints and relevant evidence metadata are cached outside rendering; draft/form/nickname/provider-only changes do not reread review sources or change a trigger identity. Deliberate review refresh invalidates the cached verdict even when stored metadata is identical. Captured source text and run journals are borrowed rather than duplicated into the cache.

The Forms picker marks the recommended form textually without moving its selected/current form or changing Enter's explicit switch-only behavior. Picker `d` (including the Return-to-Eevee row) or `/suggestion-dismiss` hides only the exact current trigger. The task-local dismissal survives restart and form/draft/nickname changes; a different evidence identity, such as a new failing run, can recommend again. Dismissal preserves the invoking draft/caret, never starts work, and is not provider/handoff context.
An idle party member already in the recommended form is named as `<name> (<form>) is free`. Availability is derived from current owned provider/command work and disappears while that member works; it does not change the evidence trigger, dismissals, form, draft, grants or provider input.

The Schema 10→11 transaction changes only the version: existing task, evidence, journal, roster and provider-preference rows are not rewritten. - Present all ten provider routes explicitly and searchably, distinguishing native Codex HTTP with scoped file tools (no CLI dependency) from the CLI agent. Unsupported effort preserves existing settings; `default` resets only when it is not itself an advertised effort. Literal arguments win over generic command search, and pasted text never dispatches.

Missing or unknown support is not permission. Disable only the affected action, explain why, and keep local browsing/notes/review available.

Private input/paste/navigation remains owned by the form while task saves settle; actual credential mutation requires committed global idle state and visible complete scope/storage disclosure. Fail closed on unsafe existing objects; never repair HOME/provider-owned files implicitly. Strip inherited ACL grants only from newly created owned objects before writing secrets. Persistence is not encryption/keychain storage. ### Navigation and editing

- Persist navigation position per task/surface: selected file/finding, scroll anchor, open drawer, and draft. Resizing hides panes without losing their state; closing an overlay restores its invoking control when it still exists. Reopening a surface already in the overlay ancestry unwinds to its saved frame instead of pushing a duplicate; repeated cross-navigation must not accumulate extra Escape steps.
- Literal command/source/search/question editors own character input; pasted slash text never invokes an action. The primary Request composer permits an isolated command popup without altering its draft/caret/suffix. Request Enter deliberately sends only after matching storage acknowledgment and local preparation; repeated Enter, modified keys and pasted newlines cannot duplicate dispatch. Editing before dispatch invalidates the prepared input rather than silently changing sent bytes. `/goal`, `/next` and criteria remain local task editors; their Enter is not model submission.
- `/reset` is a reviewed local new-task transition, not data deletion or provider reset. Default to Stay; wait for matching durable task/context acknowledgment before switching, preserve the old task/drafts in `/tasks`, and stop on save failure or user cancellation. Do not abandon active work: provider work requires explicit completion/cancellation before retry; local execution uses the existing cancel-and-wait guard.
- `/init` prepares an editable repository-guide proposal using known project identity, selects Espeon / Plan and clears write paths. Confirm replacement of a nonempty Request and retain other drafts. Building the proposal makes no provider call or file write; Enter sends through the ordinary request path. Never overwrite existing `AGENTS.md` or invent conventions automatically; reject oversized generation before mutation instead of truncating safety instructions.
- Command and attachment choosers are centered within the available screen, leaving status and fixed action hints readable. Search matches whitespace-separated terms across names/descriptions in any order, with exact-command precedence; clearing the query remains neutral. Criteria editing, specialist desks, session inspection and path selection are directly reachable through guarded commands without an intermediate chooser. Unavailable reasons remain visible, and returning to the draft preserves its caret.
- Support grapheme-aware cursor movement/deletion, Home/End, multiline paste, Unicode display width, and horizontal/vertical reveal of the caret. Do not interpret pasted slash commands as application navigation; agent commands are separately labelled and sent only through the chosen agent.
- Slash choices expose prerequisites and current scope; recheck context, storage, busy state and terminal size at dispatch. Model → reasoning and direct effort/provider choices remain local, then return to the invoking editor with draft/caret intact. Metadata needs no committed task content and reviews only actual risky connection effects. Incompatible owned sessions retain Keep current / New session / Back; no implicit session transfer or restored grant. `/role` and named form changes return directly to editing.
- Live output follows the actual transcript end only in follow mode. Manual line/page/wheel/inspection navigation pauses it; visible unread state offers a deliberate latest jump. New response or tool segments never move a paused reader. Prompt, preview and journal keys retain their own ownership. Per-segment provenance stays inspectable without splitting primary output into pages. Cache wrapped borrowed byte ranges and changed segment headers; render visible rows without copying/reflowing all history on spinner frames. Retention stays bounded and visibly reports omissions.
- Retained response items keep their original request ownership across turns and provider/role switches. When previous output remains selected during a new request or failure, label it as previous output and distinguish the current request; never relabel an old answer as a new answer.
- Streamed provider text uses cumulative best-effort redaction and may release completed words before a newline. Hold unfinished tokens and ambiguous PEM headers rather than exposing credential fragments; do not add artificial character-by-character delays. Coalesce queued snapshots in the existing bounded queues. SDK partial snapshots use a 30ms/256-byte batching threshold and always retain final completion delivery; actual provider chunk arrival remains provider-controlled.
- Links, clipboard actions, and launching an external auth command require a deliberate user action. No OSC 52 clipboard writes from tool output. Sanitize terminal escape sequences while preserving useful plain output; keep structured content separate from rendered text.
- Before discarding a changed editor draft, offer an explicit discard decision; unchanged drafts need no extra confirmation. Label the distinction between leaving an editor and closing a still-pending request view. Below minimum terminal size, preserve drafts/run state and expose safe quit/cancel; resizing must not trap the user or implicitly approve/discard work.
- Reviews lead with a concise scope/effect summary and fixed approval/cancel actions. Exact payload, provenance and lengthy technical details remain inspectable, but scrolling to their end is never an approval prerequisite. The summary must have actually rendered at a supported size; changed scope, resize, expired requests and stale identities invalidate consent.
- On a non-editing confirmation surface, an unmodified Press of `y` selects the displayed affirmative action; `n` selects cancellation/denial. Provider permission prompts may additionally offer `a` for the correlated **allow-once** decision only, never a persistent grant. Repeat, release, paste and modified characters cannot approve. Neutral Enter remains non-destructive; literal editors/search keep these letters as text.
- Pending provider input must look like waiting for the user, not ongoing editing or completed generation. Home Request/Workspace Enter opens that owner's existing pending review without sending/discarding a future draft; Alt+A deliberately opens the oldest FIFO request. These shortcuts never bypass literal editors, overlays, saved ownership or one-shot consent, and asynchronous arrival never takes focus.
- File-change review uses typed informational create/modify/path/parent metadata and a bounded real source/diff excerpt, localized by the UI rather than parsed from provider display text. Exact operation/path/parent scope receives reserved space; clipped previews never establish scope. Full content remains inspectable without end-scrolling. Neutral Enter only inspects/stays in details; a/y permits the offered one-time change only after the complete summary rendered, n explicitly denies, Esc defers. Generic/non-file permission semantics remain adapter-specific.
- File-generation previews are display-only per-call transcript items. Decode observed filename/code fragments incrementally and redact cumulatively before bounded numbered/tail display; no raw JSON, private IDs, reasoning or terminal controls. Distinguish generating/received proposal/actual pending approval/verified applied/denied/refused/interrupted/provider-reported/unknown. Completed arguments are not saved files. These items never become canonical assistant text, copied decisions, source evidence or journals. Complete-only transports show received proposals, never simulated token progress. Preserve ownership, paused anchors and future drafts; no extra scroller, forced focus, artificial reveal timer, automatic write or grant.
- Once the current request has real file output, prioritize its code viewport over duplicate preparation, evolution/advisory and carry-over banners without dismissing their retained state. Keep actual permission scope and another partner's active writer ownership visible. Old file cards must not suppress a new request's context, and compact first progress must be visible without a navigation/dismissal detour.
- Global action identity is stable across views: `/provider` and `/connect` select connections; `/response` fronts provider work; `/run` inspects execution; `/execute` reviews a prepared command; `/history` is provider observations and `/runs` local run history. Direct source, command, specialist, memory and handoff actions enter their editor/selector/review without a preliminary workspace visit. Async actions retain task/partner ownership, cancel stale intent and never guess a selected record or replay refused effects.
- Temporary task editors and direct sheets return to the same task/partner draft/caret; rebind restored task ownership and never overwrite a newly visible approval. Preserve real storage/error/return context outside sheets at 60×18 and larger. Technical correlation IDs remain inspectable after the question/decision they describe. Escape defers pending provider input; it does not answer or cancel it.

### Approval and agent-question UX

- One correlated queue holds pending requests with task, run, agent/profile, tool ID, and approval/question ID. Requests may coexist, but only the deliberately opened item owns focus. A question is not a permission grant; do not combine the two.
- Opening a request focuses its details, not Allow. Show exact command or diff when supplied, cwd/path scope, unknown effects, requested duration, and who enforces the decision. Navigation or repeated Enter on the neutral initial control must never approve.
- Offer only semantics actually supported by the adapter. An agent's `allow_always` is not automatically “allow for this Eevee task.” Broad/persistent options require explicit scope disclosure; hide them if their duration or boundary cannot be represented accurately.
- Revalidate before responding. If tool inputs, profile/config, run generation, or scope changed, invalidate the old answer and show the updated request. Expired or already-resolved requests are read-only; answering twice cannot dispatch twice.
- Esc returns to work while the request remains pending; explicit Reject responds with rejection, and Cancel run resolves pending requests with the protocol's cancellation semantics. Never remember an allow merely because a form or model was chosen.
- Agent forms preserve field values/errors, offer the provider's real choices plus supported free text, and let the user decline when the protocol permits. Do not invent answers for unsupported question schemas; report the limitation and keep the user in control.

### Operational, persistence, and evidence states

- Track independent state axes rather than one overloaded badge:
  - Task outcome: open, complete, cancelled.
  - Request: idle, connecting, running, awaiting permission, awaiting input, cancelling, succeeded, failed, cancelled, disconnected/outcome unknown.
  - Storage: draft, autosave pending, saving, saved, save failed.
  - Evidence: current, stale, ambiguous, unavailable.
- Priority in a compact header: safety/pending input, failure/unknown outcome, unsaved state, active work, then idle readiness. Reserve visible model/effort width before contextual project/partner text; below 90 columns, use concise route labels that still distinguish native, CLI and ACP methods. Secondary/full identities remain inspectable. Color accompanies text; provider/model names and task identity never disappear behind decorative art. The form capability chip (`read`, `read · run`, `read · edit`, `read · edit plans`, `read · edit docs`) is descriptive only, sits right-aligned on the status row, and is omitted rather than clipping higher-priority status text.
- Show “working” with actual observed stages, not invented percent complete, hidden-reasoning text, or a success animation. A small spinner advances about every 120ms only for visible in-flight provider work; no animation-only persistence or idle redraw timer is allowed. `--no-animation` keeps the marker static without delaying text, and `TERM=dumb` selects static output automatically. A quiet connection is not automatically a hung run. “No recent updates” offers inspection/cancel without claiming failure.
- A disconnect retains the partial journal and marks outcome unknown when completion is unobserved. Reconnect/resume is explicit and never replays a mutating request automatically. Reconcile already-applied changes before offering a new attempt.
- Save failures remain visible and retain recoverable draft content. On quit/switch, offer explicit retry-save, stay, or discard-unsaved choices; never present an unsaved task as durable. A provider-local session may persist independently and must not be confused with Eevee's own save result.
- Durable storage has an explicit schema/version and one writer. Detect another writer and expose the conflict without silent takeover. Migrate older schemas transactionally with a tested rollback/recovery path; never overwrite a corrupt or newer-schema database. Disk-full and locked-database failures retain the editable draft. Only a committed revision may be acknowledged as saved, and late acknowledgments must never regress the saved revision or label a newer draft saved.
- Coalesce implicit draft/caret/navigation/memory edits after 500ms of quiet, with a 2s maximum deferral during continuous edits outside active provider requests. Pending debounce is not in-flight I/O and must not poll the writer. A content request holds its exact committed input through dispatch, permissions and terminal acknowledgment: follow-up edits remain visibly pending in memory, including after Ctrl+S, until that ownership ends. Pre-output failure restores the original request when no follow-up was typed; otherwise retain the follow-up and submitted request separately. Outside this ownership hold, explicit saves, task/partner transitions and confirmed exit flush the latest snapshot. Safe exit cancels/waits before flushing. Only successful submission starts “saving”; old acknowledgments cannot clear newer pending work or failures.
- With active work, quit and Ctrl+C open a neutral-focus Stay / Cancel-and-exit decision, not an immediate process kill. Cancel-and-exit waits for acknowledgment or verified owned-tree exit with bounded escalation; unconfirmed teardown remains outcome unknown. Repeated keys must not accidentally confirm or force-kill. Unsaved-state choices still apply, and neither cancellation nor exit promises file rollback.
- Error cards identify layer and remedy: image loading, local storage, agent executable, auth, capability/version, transport, model request, permission denial, or command exit. Preserve technical details behind an inspect action; transient notices do not erase the selected artifact or steal focus.

### Accessibility and visual quality gates

- Keep a linear text/activity layout with the same actions and state labels; portraits are optional, never the only identity/status signal. Do not claim screen-reader compatibility before exercising a real assistive terminal setup. Reduced visual detail does not reduce approval controls or evidence.
- For the application's own true-color themes, target at least 4.5:1 text contrast and 3:1 focus/control contrast; verify selection, errors, muted text, and both backgrounds. Unknown user terminal palettes require monochrome/reverse/focus-marker fallbacks, not an unmeasured contrast claim.

Truncate display paths/titles with a visible continuation affordance; inspection reveals exact values before approval. Never truncate the only visible executable or affected scope without an expansion control.
- Run actual TUI scenarios across the supported size/theme matrix: first-run empty, missing agent/art, loaded task, long CJK draft, pending permission/question, large streaming output while scrolled, cancelled run, save failure, stale review, provider switch, and return after interruption.

## Task and evidence model

A task owns its goal, acceptance criteria, current form, agent-profile selection, independent request/storage/evidence state, decisions, source references, changes, executions, findings, permissions, and handoff. Forms exchange a compact envelope: goal, scope, evidence references, unresolved items, requested action, and completion condition. Provider session references are profile-scoped and never portable grants.

Separate observed facts, model inferences, and user decisions. Persist provenance for each. A command result contains cwd, sanitized arguments, start/end time, exit/signal status, output references, and before/after code-state identities. A passed command is not proof of every requirement.

Capture the initial working tree without overwriting user changes. Git metadata and baseline file identities distinguish pre-existing changes from session changes; concurrent external edits remain unattributed rather than falsely assigned to the agent. A code-state identity covers relevant tracked and untracked inputs, not only HEAD. Changes during a run make its association ambiguous; changes after a run make its verification stale. Display unknown coverage explicitly.

Legacy Phase 1 surfaces use a simple ready state. Planned task/request/storage/evidence axes are defined above; task completion is separate from request success and requires the explicit acceptance checklist plus visible unresolved risks.

### Task lifecycle and local retention

- Completion requires an explicit state transition. Changing the goal or acceptance criteria of a completed task requires deliberately reopening it; an old verdict must not imply the new criteria passed.
- Archive hides a task without deleting its evidence. Delete/purge is separate: preview the affected task records, drafts, output/assets, and shared references, then require confirmation with neutral initial focus and a no-effect Cancel path. Do not purge active work or silently sever its evidence.
- Redact identifiable credentials before any metadata, journal, or output-spool persistence; do not promise perfect detection. Provide configurable spool quotas and retention with visible disk-pressure behavior. Never silently evict active evidence; when capacity is exhausted, stop further capture/execution safely and expose the limitation rather than recording complete evidence.
- Retention and explicit deletion must show missing artifacts as unavailable, not empty or successful results. Preserve memory/profile records still referenced by other tasks; task deletion is not blanket shared-state deletion. Explain local scope: purge is neither secure erase nor deletion of provider-owned sessions/data. Command runners and durable-memory flows inherit these rules.

## Permissions and recipes

- Capabilities are enforced at the execution boundary, not merely described in prompts.
- Reading, writing, command execution, network access, and durable memory are separate capabilities. An external CLI without enforceable restrictions must be labelled unmanaged; do not present it as sandboxed.
- Approvals show exact arguments or shell text, cwd, affected scope where known, and permission duration. Unknown command effects remain unknown.
- Imported recipes are untrusted configuration. Loading one neither runs commands nor grants permissions.
- Evolution Stones are versioned TOML recipes specifying form workflow, allowed scope, context selection, validation commands, and completion criteria. A recipe cannot widen existing grants.
- Memory is task-local, project-local, or personal. Promotion to project/personal memory requires explicit approval and supports inspection, editing, and deletion.
- Treat terminal output, repository text, and external sources as untrusted content. They cannot modify grants or issue application commands. Strip unsafe terminal control sequences before rendering.

## Implementation stack and efficiency

Choose Rust with Ratatui and Crossterm for the native TUI, Tokio for asynchronous I/O and subprocess coordination, Serde for schemas, TOML for recipes, and SQLite through rusqlite for durable task metadata. Store large command output in bounded/rotated local files referenced by metadata. Begin with one Cargo package and explicit modules, not a multi-crate framework.

Rust offers native startup, predictable memory ownership, and no garbage-collector pauses. This is a fit-for-purpose decision, not a claim that any language is universally fastest. Model/network latency will usually dominate agent work; reducing unnecessary context and calls matters alongside rendering efficiency.

Claude uses an optional TypeScript SDK sidecar for its documented interactive lifecycle. Explicit setup/update fetches the latest stable SDK; reviewed installed metadata, loaded-code paths, dependency-tree identity, bridge revision and mandatory policy controls must match before prompt release. This is a compatibility choice, not a mandatory runtime or second UI implementation. Start it only for the selected provider; the native shell and other adapters work without it. Keep IPC narrow, versioned and bounded; compare actual resource cost rather than assuming a bridge is free.

- One terminal owner; blocking Git/SQLite/filesystem work stays off the rendering path.
- Bounded worker channels; batch stream updates. Preserve output on disk while virtualizing the visible window; do not grow an in-memory transcript forever.
- Invalidate only changed views; redraw on input/state changes, at most 30 fps during streams, never on an idle timer alone.
- Cache parsing/diff results by source identity; avoid reloading the repository or recomputing all hashes per frame.
- Launch commands with direct argv and no implicit shell. Shell execution separately identifies the executable, dialect, and exact shell text; `.cmd`/`.bat` require an explicit shell path, not a silent wrapper. Establish native process-tree ownership before offering safe cancellation: owned process groups on POSIX, Job Objects or an equivalently verified tree-ownership mechanism on Windows. If ownership cannot be established, reject the safe-cancel action rather than advertising it. Track partial output, exit status, and terminal recovery; external-agent cancellation follows its actual protocol, and timeout/forced teardown remains outcome unknown unless tree exit is verified. Never claim that cancellation undoes changes.
- Select context by scope and evidence references; do not inject every form prompt or the full historical transcript. Display provider-reported token counts separately from estimates, identify turn/session/cumulative scope, and disclose provider-added context that cannot be inspected. Do not invent savings percentages or sum incompatible counters.
- Local packet deduplication is structural, never lossy: a capture whose bytes are already present in another selected capture of the same `(root, path, source_sha256)` is emitted as a `same_bytes_as` citation that always resolves to a text-bearing entry — never a citation chain. Codex `edit_baseline` may cite a byte-identical whole-file capture instead of resending it. Distinct paths or revisions with identical text keep separate bytes. Oversized ACP tool observations are bounded by labelled head/tail elision (`truncated_by_eevee`, exact `total_bytes`/`omitted_bytes`) rather than aborting the provider session; receipts and drawers disclose deduplicated counts, and savings are never presented as provider cache hits or billing.
- Use one specialist request at a time initially. No background model chatter, automatic agent fan-out, or model calls for cosmetic transitions.
- Apply the task lifecycle and retention rules above to every persistence path, including command spools and durable memories.

Initial native local-shell performance acceptance targets, not measurements: idle CPU <1% of one core over 60s; idle RSS <=80 MiB; warm local startup to usable UI p95 <=200 ms over 30 runs; local key-to-render p95 <=50 ms under streamed output. Record hardware, release profile, terminal size, sample method, and workload. Report optional SDK bridge and external-agent resources separately **and in aggregate**; a core-only number is not total application cost. Benchmark a 10 MiB output stream and a 10,000-line diff; memory must remain bounded by configured windows/queues. Optimize from measurements, not assumptions.
