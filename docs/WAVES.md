## Ordering and gates

- Wave 1: GP01 precedes GP02; EV19 is independent. Wave 2 operations share the file executor and require a single integration owner; they are not independent competing writers.
- Wave 3: TC04 and TC02 have no dependency on each other. Wave 4 requires TC02 before TC05/D01. Wave 8 requires TC02/TC04/TC05/D01 before Q03 and A04/A06 before A07 before final Q01 composed-provider signoff.
- Local Q01/Q02/P03 evidence starts alongside Wave 1 and is refreshed for changed surfaces; it does not wait for provider credentials or Wave 8. Wave 8 is their final reconciliation home, not a ban on earlier verification.
- A04/A06 and live Q03/resource rows require separately permitted credentials and explicit live/paid authorization. Their blockers never block unrelated local waves or become synthetic passing evidence.
- Wave 6 split retained-work navigation from draft/editor changes. Wave 7's two capabilities remained separate changes; its intentional GP07 design-contract amendment preceded implementation.
- Every feature retains its exact task acceptance, neutral cancellation, immutable evidence and existing executor/store/approval authority. Each completed coherent task needs focused behavior tests, actual runtime proof, documentation and a conventional commit. A wave is complete only when all assigned task acceptance passes; partial evidence remains explicitly partial.
- Reuse bounded native profiles instead of multiplying every new case across every platform. Release qualification remains exact-source Check/all five native jobs plus public package verification when publication is requested. Waves1–7 are accepted source; Wave8, paid/live calls, push and automatic publication remain unauthorized.
