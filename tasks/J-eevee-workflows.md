# J — Eevee-specific workflow extensions

Planned after verified v0.1.29 publication on 2026-10-24. These extend shipped forms, moves/TMs, Dex, formations, held references and partner summaries rather than rebuilding them. This request authorized documentation, not implementation. See [completed foundations](COMPLETED.md), [active order](../task.md) and [design rules](../docs/DESIGN_RULES.md).

Keep the concept useful to coding: no XP, levels, streaks, random unlocks, productivity scores or provider gates. Flavor stays out of provider packets and portable handoffs. Navigation never dispatches, executes, grants or changes a frozen request. Reuse existing storage and inspectors; preserve exact drafts/carets, single-writer ownership and truthful unknown outcomes. Use focused behavior regressions plus actual English/Korean compact/wide journeys where the changed surface warrants them, not a new blanket platform cross-product. Existing rights review is not legal clearance; new assets/names require their own review.

### EV19 — Explain the next evolution before send

- [ ] Inspect why the current request would select a form and what operation it would actually permit.
- **Priority:** 1. **Needs:** —. **Builds on:** EV18, EV01A, EV01B, EV02, PK03.
- **Change:** Reuse the submission classifier and effective-policy resolver. Distinguish predicted appearance from operation, manual/automatic selection, restrictive override and ambiguous keep-current behavior. Bind the transient preview to the draft revision; submit recomputes it.
- **Accept:** Mixed intent, quoted source, ambiguity and explicit read-only requests produce a preview consistent with actual explicitly submitted loopback receipts. Editing invalidates it; inspection preserves draft/caret and performs no selection change, dispatch or approval answer. Exercise English/Korean and both sizes.
- **Watch out:** No model classifier, confidence/ability score, custom routing language, automatic rule change or additional animation.

### MV09 — Semantic move and TM replacement review

- [ ] Understand the exact old/new definition before replacing or teaching a move.
- **Priority:** 2. **Needs:** —. **Builds on:** MV01A, MV01B, MV01C, MV04, MV05, MV07, MV08A, MV08B.
- **Change:** Extend existing replacement/teach/import review with ordered argv including empty arguments, cwd, pins, instructions and criteria. Distinguish a name-only edit. Bind old record/revision and proposed definition; concurrent rename/replacement invalidates review.
- **Accept:** Review one changed argument and a same-name imported TM, then exercise cancel, restart, stale review and one ordinary explicit use. Cancellation preserves inventory and draft. Historical usage remains attributed to the original record; taught copies do not silently synchronize.
- **Watch out:** Reuse new-record/forgotten-old semantics where applicable; never rewrite history. Portable TMs contain semantics only, not local IDs, grants, teacher identity or historical evidence. No parallel executor.

### PK07 — Dex recurrence versus historical resolution

- [ ] Distinguish a recurring failure from a previously resolved, now stale observation.
- **Priority:** 2. **Needs:** —. **Builds on:** PK05A, PK05B, EV10A, EV10B, EV12, PT10, R02.
- **Change:** Compare existing failure/resolution references using command, cwd, source, supporting evidence and passing-run identities. Show missing/stale support honestly. A selected evidence relay may reuse the reviewed Umbreon flow without sending or executing.

### PT12 — Formation mapped-party readiness preview

- [ ] See whether mapped partners can stage a formation and whether their routes are ready to submit.
- **Priority:** 2. **Needs:** —. **Builds on:** PT11, PT05B, PT07A, PT08A, EV17, PK04, MV02A.
- **Change:** Extend mapping review with local move availability, held-reference availability, cached remembered-route readiness, nonempty drafts and busy writer ownership. Separate staging eligibility from submission readiness; unknown is not unavailable.

### PK08 — Deliberate held-reference renewal

- [ ] Review and explicitly renew a changed approved-memory reference or a user-selected replacement file.
- **Priority:** 2. **Needs:** —. **Builds on:** PK04, S02, C02, C03A.
- **Change:** Show old/new identity and available retained content through existing source review. If old content is unavailable, say so rather than inventing a diff. Reuse the one-reference-per-project/partner/form store; renewal changes configuration, not active pin/selection.
- **Accept:** A changed memory revision makes the old held reference unavailable until renewal. Exercise moved-file replacement, cancel, exclusion/revocation/owner races and restart. Cancel preserves old configuration and current basket; renewal never alters an already frozen request or silently selects content.
- **Watch out:** No duplicated payload, automatic latest revision, rename tracking, source search or multiple equipment slots. Existing containment and no-link rules remain authoritative.

### PK09 — Partner contribution drill-down

- [ ] Open attributed task/form contributions from the partner summary and route context.
- **Priority:** 2. **Needs:** —. **Builds on:** PK02, EV05, EV06, PT06A, PK06.
- **Change:** Navigate to paged existing artifact/evidence inspectors filtered by retained task, producer and form identity. Preserve actual producers, freshness and unknown/unavailable states. Current artifacts have no explicit route-visit foreign key: route history is navigation context, not proof that a visit caused an output.
- **Accept:** Two partners produce distinct retained outputs; capture/run/review, a form-only visit, rename/release and purge retain truthful attribution. Legacy unknown remains unknown, form-only visits create no evidence, and timestamp proximity never invents authorship or a visit link. Compact paging/back navigation and explicit cross-task navigation preserve drafts and ownership.
- **Watch out:** No new ribbons, scores, rankings, generated retrospective, activity counters or duplicated payload. Label task/form contributions unless an exact causal link is actually retained.
